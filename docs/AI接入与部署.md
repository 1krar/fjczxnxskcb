# 千问 AI 接入与部署

## 已预设

- 服务：阿里云百炼普通 API，北京地域。
- 模型：`qwen3.8-flash`；关闭思考，使用严格 JSON Schema 输出。
- 默认接口：`https://dashscope.aliyuncs.com/compatible-mode/v1`。
- 浏览器只请求同一网站的 `/api/ai`，百炼密钥只由 Cloudflare Pages Functions 使用。
- 通知识别保留原话。把表单字段、字段说明、原通知参考日期和本班课程清单交给模型，由模型理解完整通知，直接填写规范日期、24小时时刻、地点、节次、课程和明确交代的准备事项。每个字段附原文依据，可同时引用不相邻的时段与钟点。本地不再用中文时间匹配规则重新解释模型答案。
- 字段区分原文明示、结合上下文、确有歧义、原文未提到。未提到的可选信息留空，不等同待确认；确有歧义时才提示。模型输出的结构用于指导，接收时按字段容错：漏字段补空，全角时刻等记法整理为表单格式；缺少引用、状态标签矛盾不再整条拒绝。不能直接使用的字段单独说明，保留其他答案。结果先展示，点击应用后才写入表单，缺失答案不擦除手工已填信息。
- 应用结果会展开并定位到时间表单：活动开始时间填入具体时间，起止区间单独保留；明确的作业截止优先，不把相关小节区间猜成截止。保存、重新打开和备份恢复均保留区间。只有时刻、没有日期时先保留已知时刻，不自动生成确定日期的提醒。
- AI提炼的事项名称、时刻的开始/截止含义一起保存；首页卡片突出时刻、名称、地点和准备，完整原通知从详情查看。旧记录仍可读取，名称和时间含义可在表单里自行修改。
- “下次某课前”的课程与关系由模型识别，本地按真实课程数据查询对应上课时间；明确小节由真实冬夏作息查表，不让模型凭常识编作息。只有“下周”等模糊范围时不猜具体截止日。旧消息的相对日期由模型以用户设置的原消息时间换算。
- 活动可存为候选日程，再使用既有冲突检查决定是否参加；课程变更通知不会自动覆盖课表。
- 每日一句每天自动尝试一次，可手动换句。记录变化后旧事实的句子不再显示，可手动重新生成；失败显示本地内容。

## 在 Cloudflare 配置

在 Pages 项目的生产环境配置以下内容，然后重新部署：

| 类型 | 名称 | 内容 |
| --- | --- | --- |
| Secret | `DASHSCOPE_API_KEY` | 北京地域百炼普通 API Key |
| Secret | `AI_ACCESS_TOKEN` | 自行设置的6位数字口令；也兼容24至512位、不含空格的长口令，不能使用百炼 Key |
| D1 binding | `AI_DB` | 新建专用 D1 数据库并以此名称绑定 |
| 可选变量 | `AI_DAILY_LIMIT` | 每个访问口令每日调用上限，默认20，范围1至200 |
| 可选变量 | `DASHSCOPE_BASE_URL` | 百炼北京工作空间的新式接口地址；不填时使用上述默认地址 |

数据库首次使用会自动建立 `ai_quota` 和 `ai_auth` 表。只保存服务端加盐的标识、北京日期、调用与验证计数及过期时间，不保存通知、课表或 AI 输出，也不保存原始 IP 地址。数据库是调用限额用途，个人事项的云同步尚未实现。为预览环境配置时，建议使用独立的口令与数据库，避免共享生产额度。

打开网站 → 更多 → API 与服务连接：

1. 填写网站访问口令，选择需要的 AI 功能并保存。
2. “验证配置与口令”只检查配置及授权，不调用百炼。
3. “测试模型连接”实际调用一次；成功才说明百炼密钥和模型权限有效。

浏览器中不填写百炼 Key。网站访问口令仅存于本次浏览会话；重新打开浏览器可能需要重填。密钥不应写进源码、GitHub、URL、日志或普通 JSON 备份。不要在聊天中发送真实密钥。

## 限额与失败处理

- 通知识别、每日一句和模型测试共用每分钟2次、每天默认20次的服务端额度。
- 分钟按服务端自然分钟计数；浏览器额外按滚动60秒限制。每日按北京时间午夜重置。
- 预留调用次数后才请求模型。上游失败仍计一次，避免错误重试持续产生开销。
- 访问口令缺失/错误、用量数据库不可用时不会请求百炼。关闭浏览器开关停止自动请求。
- 支持6位数字口令。同一出口 IP 在15分钟窗口内累计5次验证失败后，暂停该窗口内后续验证；全站30次失败/异常尝试后也会暂停。正确口令同样受暂停限制，避免通过不停猜测绕过限额。成功验证不消耗失败次数，数据库不可用时拒绝验证。IP 只取 Cloudflare 提供的 `CF-Connecting-IP` 并加盐散列，不使用可任意伪造的转发头。短口令比随机长口令更易猜中，尝试限制仅降低风险。
- 一次通知最多识别6项，不自动批量创建提醒。无日期的随手记不视为信息不足；有实际歧义时才标为待确认。
- 原文引用可选。能匹配到原文的才显示为引用；AI的归纳解释不会冒充原文，也不会因为引用写法不一致而丢掉已识别的答案。课前关系没有关联课程时不进行课表推导，普通“提前到场”属于准备事项。
- 通知超时或结果完全无法读取时不自动写入；日期无效等问题只影响对应字段，原话和其他有效结果保留。
- 结构化输出只保证格式，不保证语义正确。重要时间仍可以在预览与表单中修改。
- 提取协议使用版本2；旧网页请求会收到刷新提示，不消耗模型额度。字段规范与研究依据见[通知识别方案](./通知识别-字段驱动方案与研究.md)。

## 本地开发

`local_preview.py` 是静态预览，不运行 Pages Functions；此时仍能保存个人记录、使用本地每日一句。要测试真实 AI，使用已配置的在线网站，或使用 Wrangler Pages 开发模式，并在未提交的 `.dev.vars` 和本地 D1 binding 中配置。`.dev.vars` 已被忽略。

验证命令：

```text
node tests/notice-model.test.mjs
node tests/ai-service.test.mjs
node tests/daily-assistant.test.mjs
node tests/personal-items.test.mjs
node tests/agenda.test.mjs
```

网关测试使用模拟的模型响应与真实内存 SQLite 验证配额，不会消耗真实百炼额度；实际模型连通性需要在配置真实密钥后验证。
