# UI／UX 全面自检与改版方向

日期：2026-10-24，北京时间。检查基线：`e2516a4`。

本轮为界面诊断和改版规划，应用代码、个人数据和正式部署未改动。

后续进展：用户确认实施后，已按本诊断完成主要路径与层级改版，详见 [实施与验收记录](UI改版实施与验收-2026-10-24.md)。本文保留诊断时的原始测量与问题描述。

## 1. 结论

目前最突出的问题是：功能按开发批次逐层叠加，页面缺少明确的主任务。大量说明、配置、空列表与日常操作同时出现，卡片、标题、蓝色按钮承担的视觉权重也过于接近。

学生常用的路径应当直接可见：看接下来去哪上课、记下通知、选明天衣服、确认今天穿过什么。首次使用、已经录入、没有课程、正在上课等状态，需要各自的页面重点。

此前功能、备份、溢出检查已覆盖部分稳定性，但没有充分验证首屏任务顺序、读起来是否轻松、日常操作是否顺手。这些是本轮重点。

## 2. 检查方法与范围

- 浏览器实际检查390×844手机视口的11个路由：首页、衣橱、事项、周课表、日历、更多、API、数据、分析、对比、提前提醒。
- 另外检查1366×900桌面视口的首页、衣橱、周课表、更多和数据页。
- 实际查看快速记录弹窗；有记录的衣橱状态复用同一版本的隔离验收截图。未向真实衣橱或事项添加测试内容。
- 读取相关DOM尺寸、颜色、透明度、字体和顺序，并与CSS／渲染代码交叉检查。
- 使用现有 `ui-ux-pro-max` 的审查规则；检索SkillHub公开目录，并核对GitHub原作者的设计技能和动效项目。
- 本轮模拟视口首屏未见页面根元素横向溢出。数据表内部横向滚动与页面溢出不同，仍需要单独判断是否适合手机。
- 真机软键盘、真实触摸拖动、200%文字放大、深色实际呈现尚未完整验证。相关内容保留为下一轮验收项，不能据此宣称全面通过无障碍标准。

截图与测量保存在本机忽略目录 [本机私有审查目录](D:/课程表程序/.private/ui-audit-2026-10-24/)，不随网站发布。手机矩阵、桌面矩阵、配色计算与技能检索结果分别保存为JSON。

## 3. 已确认的问题

优先级：P1为明显影响理解或主要操作的问题；P2为视觉、效率与一致性问题。本轮没有发现必须停用网站的P0问题。

### P1-01 空衣橱的首屏任务顺序不合适

实测390×844、没有录入衣物时：

- “这天怎么穿”卡片约575px高。
- 首屏先显示日期、校园跑、保存跑步安排、天气、AI想法输入、AI配置和多段说明。
- 真正的“录几件常穿衣服”展开入口起点约为页面y=827px，已经处于首屏底部以下；底栏还会占用可见区域。
- 空状态整页约2724px，约为视口高度的3.2倍。

影响：还没完成首次录入，就先遇到依赖衣物数据的功能和配置。

处理：空衣橱直接显示“先录一件上衣和下装”；隐藏依赖衣物的推荐、批量洗晒与空统计。已有衣物后再进入正常推荐界面。技术来源：[wardrobe.js](D:/课程表程序/js/wardrobe.js:50) 的统一模板与 [daily.css](D:/课程表程序/css/daily.css:29) 的衣橱布局。

### P1-02 课程被过度淡化，可读性不足

手机和桌面均可见已结束课程整体发灰。代码中 `.m-agenda-item.finished` 设置 `opacity: 0.45`，桌面过去课程也有整块透明度处理。课程名称、教室、时间与按钮一起变淡，回查教室或旧课程时很费力。

处理：保持关键文字正常可读，用“已结束”弱标签、时间轴标记或轻背景表达状态。课程状态只影响必要的提示，不让整条内容失去可读性。

### P1-03 周末打开课表会回到本周一

检查日期为10月24日星期六，周课表默认选中10月19日星期一；顶部只列周一到周五。[schedule.js](D:/课程表程序/js/schedule.js:156) 在周末将默认选中日回退到1。这会使打开页面后的时间方向不够明确。

处理：周末明确显示今天与本周课程已结束的状态，提供下一有课日／下周入口；不悄悄把默认选中日移到过去。保留浏览历史时，清楚区分“今天”和“正在查看的日期”。

### P1-04 底栏文字太小、未选中文字太浅

DOM实测未选中导航文字为10px、`#94a3b8`。该颜色对白色底的计算对比度约为2.56:1。普通文字通常需达到4.5:1，未选中导航仍可点击，不能当作禁用控件处理。[W3C：文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

处理：底栏文字建议12—13px，使用更深的次级文字色；选中态同时依靠图标、字重或标记识别。现有底栏整块点击面积较大，这项问题主要是文字辨识度，不能把它误写成点击面积不足。

### P1-05 导入新课表的主要入口被放在后面

数据页先展示学期、班级表、校验结果，再出现课表更新。对于“我要读取新数据”的使用目标，前面的管理信息占用了首屏。

处理：首先展示当前使用的数据版本／导入状态和“导入课表”；学期详情、其他班级统计、校验细节折叠。校验结果明确说明检验范围，避免“未发现异常”被理解成课程现实安排也已核实。

### P2-01 事项页有重复入口，空状态仍展示重型筛选

没有事项时仍有四个状态计数、搜索、课程筛选、空状态卡和备份区；顶部和右下角同时出现“记一下”。

处理：空状态直接给可输入的一句话或唯一记录入口。有事项后再展示搜索／筛选；历史与备份收在辅助位置。页面已有清晰主入口时，避免再放一个同权重悬浮按钮。

### P2-02 设置、API、提醒等页面的悬浮按钮覆盖说明

“记一下”悬浮按钮在多个配置页面持续出现。在手机提醒设置截图中，它覆盖了表单说明的右下部分。全局记录入口有价值，但位置和体积需要随场景协调。

处理：内容页保留轻量记录入口；长表单中收敛为顶栏入口，确保不盖住保存、错误或关键说明。统一固定控件的安全区和内容避让。

### P2-03 “更多”三列入口造成长名称碎裂

实际截图中“提前提醒与大A”的A、“API与服务连接”的末字会换到下一行。七个同样大小的入口块也没有表现日常频率与配置层级。

处理：改为分组列表：日常准备、课程与日程、设置与数据。衣橱、日历等放在更容易发现的位置；长名称在合理宽度内完整显示。首轮可保留现有四项底栏，先整理“更多”内部结构。

### P2-04 页面的卡片、标题和辅助说明缺少统一层级

首页已经有轻标题和行列表；衣橱则继续使用大白卡、粗标题、嵌套折叠与长段说明。页面切换时视觉语言变化明显。大量解释性文字与主要内容一起常驻，也让界面像一张配置表。

处理：统一四种结构：主要信息区域、普通行列表、辅助折叠、编辑表单。普通模块用轻标签；内容名称、时间和教室比模块名称醒目。规则放在相关控件附近或帮助折叠中，首次出现时适度解释。

### P2-05 衣物与穿搭记录的操作没有明显主次

同版有数据截图中，每条穿搭记录同时展示修改／评分、撤销实穿、取消计划、收起等蓝色文字操作；单品行还展示状态、7／30天统计、上次穿着、洗后记录、下拉选择、调整、收起。字段和操作较多，阅读节奏碎。

处理：记录行保留“这套穿过了／评分”等当前主要动作，其余进菜单；已确认后以内容和体验为主。衣物列表默认展示名称、状态和一项近期统计，完整统计与洗晒历史点开查看。批量操作只在选中衣物后出现，并按当前状态突出下一步操作。

### P2-06 手机衣橱的视觉顺序与DOM顺序不同

手机CSS通过 `#add-garments { grid-row: 2; }` 把录入卡移到推荐之后。DOM仍先放穿搭记录、衣物、搭配，录入卡在后面。键盘／读屏顺序可能与视觉顺序不一致。

处理：按实际任务顺序组织DOM；响应式只改变列布局，避免跨越主要内容重排操作区。这与首页已经采用DOM真实重排的处理原则保持一致。

### P2-07 日期与状态需要持续统一

当前持续打开的实例中，首页已为10月24日，日历仍选中10月23日，今天另外以下划线标出。用户主动查看过去日期是合理行为；不能把所有不同日期都认定为错误。但 [agenda.js](D:/课程表程序/js/agenda.js:9) 的初始选中日期只在模块加载时计算，跨午夜没有区分“跟随今天”和“用户指定日期”。

处理：建立明确的日期跟随策略，并保留“回到今天”；下一轮增加跨午夜复现验收，区分主动历史浏览与默认日期陈旧。

### P2-08 保存方式、反馈位置不一致

显示设置即时生效；校园跑需要按保存；长提醒表单也需要保存；衣橱的部分成功信息写到页顶。用户在页面较下方操作时，未必能看到结果。实穿记录操作后焦点回到记录入口，较长列表中也可能失去原行位置。

处理：简单开关与复杂表单分别建立固定提交规则。成功反馈在操作附近出现；完成／收起提供撤销；编辑关闭后尽量回到原条目。长表单的保存与错误在小屏上应容易到达。

## 4. 已有基础应继续保留

- 当前／下一次课与后续课程分开，后续课程按一次课合并，真实小节及课间保留。
- 每日一句已缩成可关闭横幅；无需再次放大成独立大卡。
- 普通事项默认一条，长期提示和截止事项分开。
- 计划、实穿、评分和洗晒状态的含义已区分，不为了简化界面而混成一个按钮。
- 已有原生控件、焦点样式、语义颜色与动效变量；可在此基础上收敛。
- 没有课程或事项时，下方留白可以保留。无需为了填满屏幕而增加无关统计或建议。

## 5. 收敛后的页面结构草案

### 首页

```text
每日一句：一行轻通知
日期 · 天气

有课：当前／下一课、教室、时间、必要准备
无课：今天无课为主；下一有课日作为轻量预告

要记得：默认一条
后续课程：按一次课合并，可折叠
出门／明日准备：简短摘要，点开查看
```

### 衣橱

```text
首次进入：录一件上衣、下装 → 再给真实候选

已有衣物：
今天／明天／选择日期
天气与活动约束：一行摘要
主方案 → 选这套；另外两套按需展开
今天实穿：确认／修改／可选评分
我的衣物：简洁列表，细节按需展开
偏好、洗晒细节、备份：辅助区域
```

### 事项与更多

- 事项首屏围绕“先记下来”；列表和搜索服务已有记录。保持快速捕获入口唯一且稳定。
- “更多”以分组行列表组织功能，把日常入口与配置／数据入口区分。
- 手机日历优先考虑周条＋所选日日程；月视图仍保留，适合查某天时展开。
- 课表回查时保持教室／时间可读；周末和跨周切换明确显示日期方向。

## 6. 审美与统一规范

建议方向：干净、安静、内容明确的校园随身手册。沿用蓝色与中文系统字体，通过层级、排版和少量状态色形成识别。

| 维度 | 建议 |
| --- | --- |
| 字号 | 页面标题20—22px；课程／方案内容16—20px；正文14—16px；辅助12px；底栏12—13px |
| 主次 | 每屏一个明确主动作；普通链接、编辑与低频操作降级 |
| 间距 | 使用4／8px基础节奏；行内紧凑，任务组之间16—24px；大留白用来分组 |
| 容器 | 主要信息区域用卡片；普通列表、历史与设置行使用轻分隔 |
| 颜色 | 蓝色服务选中与主要操作；状态色只表达含义；关键文字保持足够对比 |
| 衣物 | 可使用统一类别图标和已录入颜色标记，保留文字；不要求为每件衣服拍照 |
| 文案 | 先给内容和动作，再提供规则与解释；原话、来源、证据仍可展开查看 |

这套方向属于针对本项目的设计判断，不是研究证明的唯一方案。目标是让用户迅速理解“接下来做什么、点哪里”。

## 7. 动效重点与实现约束

现有代码已有页面入场、按压、导航指示与部分脉冲动效；主要缺口是操作前后内容位置的连续性、局部保存反馈以及列表变化的可追踪性。

| 场景 | 建议反馈 | 初始时长建议 |
| --- | --- | --- |
| 按下／选中方案 | 轻微颜色或边框变化，明确选中态 | 80—120ms |
| 展开详情／备选 | 保持标题与阅读锚点，局部过渡 | 140—180ms |
| 完成、收起、撤销 | 条目局部退出／恢复，附近出现可撤销反馈 | 约150—200ms |
| 排序 | 被拿起条目有明确状态，相邻条目平滑让位 | 约160—220ms |
| 异步识别／保存 | 按钮内真实进度状态，成功后局部更新 | 随实际请求 |

时长是本项目待实测的初始参数。自动天气刷新、计时和备注变化不触发整页入场；减少动态效果时保留文字状态与焦点反馈，取消不必要位移。

当前多处使用 `innerHTML` 重建整块列表，长按排序则直接移动DOM。加入列表动画前应保持条目身份与稳定节点，避免每次更新都被识别成整批删除／插入。已有键盘排序和取消机制应保留。

[AutoAnimate](https://auto-animate.formkit.com/) 支持原生JavaScript的子元素添加、删除和移动，并响应减少动态效果偏好，可作为局部列表动效候选。其作用范围和布局限制需要结合当前渲染方式验证，不直接作用于整页。

## 8. 技能与开源参考的取舍

- **本轮实际使用：`ui-ux-pro-max`。**读取其Web审查规则、视觉层级、内容优先、焦点／顺序、对比度及减少动态效果要求。定向检索中的部分匹配不适用主次按钮问题，最终以完整规则索引和实际界面证据判断。
- **[Impeccable](https://github.com/pbakaus/impeccable)**：其公开设计工作流区分可测的技术审查与视觉／体验批评，适合本项目后续做减法、层级整理与精修。参考其流程，不把自动检测分数当作审美结论。
- **[Anthropic frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design)**：适合确立与具体产品有关的视觉方向、字体层级与有意义的交互反馈。本项目采用中文阅读舒适和校园日常效率作为判断依据。
- **[FormKit AutoAnimate](https://github.com/formkit/auto-animate)**：原生JS可使用的列表过渡候选，适用于后续局部交互验证。
- **[Memos](https://github.com/usememos/memos)**：公开的个人记录与时间流项目，可用于快速捕获和记录组织的进一步参考；本轮没有对其运行页面做完整对照验收。

另通过 `find-skill-skillhub` 检索UI、UX、审美、motion四组关键词并留档。检索到 `ux-heuristics`、`motion-lab`、`ui-new` 等候选；泛化介绍、下载量与“大师”式名称不能验证实际适配度，因此未把它们当成已安装或已运行的技能。本轮没有安装第三方软件或技能。

## 9. 建议实施顺序与验收

### 第一轮：可读性和主要路径

1. 修正过去课程整体淡化、底栏小字和周末日期默认行为。
2. 空衣橱改成首次录入路径，数据页将导入放在前面。
3. 合并事项重复入口；收敛表单页悬浮按钮。

验收：390px首屏可以开始录衣物；回查课程可直接读到时间和教室；周末进入课表知道正在看哪一天；每页主动作明确。

### 第二轮：统一页面结构

1. 衣橱录入、推荐、实穿与历史分组；空状态和有数据状态分别处理。
2. 更多页分组列表，手机日历以当天日程为重点。
3. 统一标题、按钮、行高、说明和保存反馈；视觉顺序与DOM顺序一致。

验收：使用代表性长课名、长通知、两条实穿、待洗／晾晒状态；确认筛选、折叠和排序偏好不丢失。实际触摸和键盘都能完成核心操作。

### 第三轮：局部动效与细节

1. 保持稳定DOM和阅读位置，再给展开、排序、完成增加过渡。
2. 测试减少动态效果、真实软键盘、文字放大、深色以及低性能手机。
3. 对照截图与日常使用过程复查，修正真实困难后再扩大功能。

这轮建议先完成可读性与页面结构，再继续增加AI个性化入口，避免新功能继续放大现有布局问题。
