# 通知识别：按字段理解并填写

## 目标和纠正

用户粘贴群通知或记下口头安排，模型阅读完整语境，找到表单所需的答案，再给出可修改的预览。

旧设计让模型只截取原文表达，再由本地中文匹配规则换算时刻。截取阶段容易丢掉较远的时段修饰，本地规则又限制了模型已经具备的理解能力。因此改为模型直接给出规范值；本地只负责校验、真实课表查询和保存。

## 输入与输出

输入只包含本次通知、可修改的原消息参考时间（北京时间）、本班课程名称清单和用户明确选择的课程。不会把所有个人记录一起发送。

由统一字段规范生成模型的严格 JSON Schema、字段说明和接收时的格式整理。结构约束用于指导模型，不要求用户粘贴规范通知；模型回复中辅助字段缺失也不能整条拒绝。字段包括：日期、开始、结束、提交截止、地点、关联课程、起止小节、到场时间、报名截止日期与时间、原文明示的准备事项。一个消息可拆成最多6项，时间和地点必须归属各自事项。

每个字段包含四部分：

| 内容 | 作用 |
| --- | --- |
| `value` | 可直接填表的规范值，如 `15:40`；不是原文片段 |
| `status` | `stated` 原文明示、`interpreted` 结合上下文、`uncertain` 确有歧义、`missing` 原文未提到 |
| `evidence` | 可选原文引用；允许同时引用不相邻的“下午”和“3点40”；缺少引用不影响有效答案 |
| `note` | 需要时给一句简短依据或歧义说明，不索要所有空字段 |

例如通用示例“下午社团说明会3点40开始，在教学楼甲，请提前到场”应得到开始 `15:40`、地点“教学楼甲”、准备“提前到场”。日期、结束和具体到场时刻留空；不能编造今天、活动时长或提前10分钟。

## 本地程序的职责

1. 按字段整理类型、24小时时刻和真实日历日期，不把规范时刻再次转成中文规则解析。漏字段补空；状态与值矛盾时优先保留可用答案。引用仅作为可选解释，只显示能在原文找到的部分，不要求逐字引用才接受模型理解。
2. 模型识别“下次课程前”后，查询本班真实课程；识别第几小节或课间后，查询该日期的冬夏作息。找不到唯一对应才说明实际歧义。
3. 展示每个字段及其依据；点击应用后填入已知信息，原话不丢失，缺失答案不清空手工信息。
4. 只有时刻没有日期也可以保存；没有日期就不生成确定日期提醒。候选活动不会占用已确认的忙碌时段。
5. 某个日期、时刻不可用时，仅该字段显示具体问题，其他答案照常应用；课程名称没有匹配时暂不关联，缺少课程的课前关系不凭空推导。网络失败或回复完全无法读取时保留原话。课程变更不自动覆盖导入课表。

格式检查和原文引用都不能证明模型理解正确。引用不匹配也可能只是模型做了归纳，不能据此把整条消息拒绝；保留AI整理的字段，并明确它不是原文直引。需要真实模型评测和用户可修改预览共同控制。

## 采用的策略与暂缓的策略

- 采用字段说明与严格结构输出，让模型承担语义归一化；不是继续扩写中文时间正则。
- 保留逐字段短依据，有助于定位“没找到”“解释错”“回填错”分别发生在哪一步。
- 不把“模型自报高置信度”当作正确保证，不因可选字段空白反复催补。
- 当前不默认再调用第二个模型复核。双调用增加等待与费用，也可能重复相同错误。先用真实错误样例定位，再考虑仅对实际歧义提供用户主动复核。
- 不引入完整代理框架、向量库或网页自动抓取。单次通知提取只需清楚的字段合同和真实课表查询。

## 验证分层

- 单元测试使用固定模型输出：检查分散引用、缺失与歧义、记法整理、字段局部保留、课表查询、无日期时刻持久化和提醒边界。这不代表模型准确率。
- 浏览器测试使用模拟接口：检查手机预览、应用、保存、重新打开、候选活动和原话保留，不消耗百炼额度。
- 真实百炼评测需要已授权的会话：用独立输入重复验证非相邻时段、多人多事件、教室数字、否定更正、相对日期与真实歧义。分别记录字段正确率、遗漏、无依据补全和耗时；不能只统计 JSON 合法率。用户原始通知保存在本地私有评测材料，不提交公开仓库。

## 研究与实现参考

以下论文是自然语言处理会议或预印本，未称其为“核心期刊”。它们支持方案选择，不保证某个模型在本应用中的准确率。

- [Instruct and Extract（EMNLP 2023）](https://aclanthology.org/2023.emnlp-main.620/)：按用户提供的提取指令和表头组织信息，直接对应“先告诉模型需要哪些字段”。
- [UIE（ACL 2022）](https://aclanthology.org/2022.acl-long.395/)：用统一结构和提取模式表达信息提取任务，支持字段结构驱动的设计。
- [Instructor 开源项目](https://github.com/567-labs/instructor)：以类型结构定义输出，再做验证；本项目采用相近的字段合同思想，未增加其 Python 运行依赖。
- [JSONSchemaBench](https://arxiv.org/abs/2501.10868)：格式约束、覆盖和输出质量需要分别评估；合法 JSON 不能代替语义正确性检查。
- [百炼结构化输出文档](https://help.aliyun.com/en/model-studio/qwen-structured-output)：当前千问模型的严格 JSON Schema 接入依据。
