# 大学生日常助手：构思与实施档案

记录日期：2026-10-20。本文保存本轮讨论的完整方向、用户已确认的使用习惯、研究依据、实施顺序和存储决策，作为后续开发依据。

## 1. 项目现状

- 项目：课程控制台，原生 HTML / CSS / JavaScript 静态网页。
- GitHub：<https://github.com/1krar/fjczxnxskcb>。
- 已有网站：<https://xnxskcb.pages.dev/>，由 Cloudflare Pages 承载。
- 已有功能：今日状态与倒计时、周课表、课程详情、空档统计、学期进度、课程/教师/教室分析、三个班级对比、课表文件导入与恢复。
- 学校抓取脚本：电脑运行“抓取课表.cmd”，本人完成学校登录与验证，脚本读取各周课表并生成 JSON。
- 学校暂无第三方接口授权；当前采用“抓取后导入文件”的更新流程。
- 原始课表 JSON 放在项目 data 目录；用户设置和导入的班级覆盖数据保存于浏览器 localStorage。

## 2. 用户已经确认的需求

1. 主要服务个人大学日常，优先适配手机。
2. 忘记作业截止、临时找教室、有空不知道先做什么，这些问题都会出现。
3. 作业和考试等通知主要来自 QQ 群与老师课堂口头通知。
4. 目前记录习惯较少，应降低记录和维护门槛。
5. 上课时方便用手机当场记一句话。
6. 希望保留完整构思，然后开始实施。
7. 关心数据如何保存，以及能否放在 Cloudflare、GitHub 等云端。

## 3. 产品方向

围绕课表安排一天，减少忘事、找信息、重复做决定的麻烦。首页帮助回答：下一节在哪里、今天要记得什么、接下来有哪些安排。

体验原则：

- 一句话即可保存，只有正文必填。
- 分类、课程、日期都可以稍后补充。
- 从课程卡片进入时，自动关联这门课程。
- 口头通知不完整时，允许保持“时间待确认”。
- 保存通知原文，便于回看与核对。
- 识别出的时间只作为建议，用户确认后才进入确定日期。
- QQ 转发消息中的“明天”等相对时间缺少原始发送日期时，要求核对。
- 首页只突出少量与当下有关的信息。
- 空档建议包含休息，保留用户选择权。
- 通过真实使用验证是否省事，减少需要额外维护的内容。

## 4. 当前界面观察

| 现象 | 影响 | 调整方向 |
| --- | --- | --- |
| 凌晨仍展示课前准备与很长倒计时 | 与当前生活场景不匹配 | 夜间优先明早课程、待带物品，临近上课再强调倒计时 |
| 今日页与课表页都以课程时间线为主 | 页面用途接近 | 今日突出眼前事项；课表负责查日期与课程 |
| 课表空档直接标为空闲 | 包含吃饭、走路、准备和休息 | 区分课表空档与用户愿意安排的时间 |
| 分析、数据占据手机底部入口 | 低频操作占据常用位置 | 手机导航逐步收敛为今日、课表、待办、更多 |
| 统计主要是课程、教师、教室数量 | 帮助描述课表，较少支持日常行动 | 增加截止事项、临时变更和个人安排 |
| 个人覆盖数据仅在单个浏览器 | 换设备时不同步 | 提供备份恢复，再增加有身份验证的云同步 |

## 5. 完整功能构思

### 5.1 随手记录

- 全局“记一下”入口，在手机拇指容易触达的位置。
- 课程详情中提供同名入口并带入课程。
- 使用手机键盘自带语音输入；输入方式由用户决定。
- 示例：“数学第三章作业，下周五交”“明天英语课带耳机”“下周换到315，具体时间再确认”。
- 首屏只要求正文，其他选项折叠显示。
- 输入内容采用纯文本展示，保留换行。
- 编辑、完成、撤销完成、移入回收站及恢复。

### 5.2 课程与事项关联

- 作业、考试、带物品、课程变更、普通笔记五类。
- 以学期、班级、课程名称关联个人事项。
- 每门课详情可以看相关未完成事项。
- QQ 消息可复制粘贴到正文，来源可选 QQ 群、课堂口头、其他。
- 截止日期/时间、下一步行动可选。
- 无日期事项可以明确标记待确认，也可以只是无日期笔记。
- 记录教室变更时保留事项及原文；后续再增加实际课表例外覆盖，避免未经确认就修改学校数据。

### 5.3 今日页

- “今天要记得”：临近截止、待确认通知、下一节课相关事项。
- 课程结束或无课时仍可查看个人事项。
- 事项完成后立即反馈并可恢复。
- 下一节课位置优先清晰显示；教师等次要信息可收起。
- 夜间状态与明日准备后续单独优化。

### 5.4 个人安排与临时例外

- 一次性/重复活动：社团、运动、项目、约饭、取快递等。
- 临时调课、停课、换教室、考试。
- 学校课表与个人安排冲突检查。
- 周末支持个人日程。
- 完整的课表例外与个人日程排入下一阶段。

### 5.5 空档与下一步建议

- 用户可设置吃饭、走路、准备、休息的时间。
- 计算扣除这些安排后可使用的时间，避免把课表空档全部当成学习时间。
- 用任务预计时长推荐少量可选事项，预计时长保持可选。
- 支持现在做、另找时间、留作休息。
- 任务可添加一个容易开始的动作，例如“先打开作业要求”。
- 接受建议后才写入个人安排；后续按真实使用调整推荐规则。

### 5.6 课程复习

- 课后写几个回想问题。
- 分散到后续日期再次练习，避免全部挤到考试前。
- 可考虑与 Anki 等现成工具衔接。
- 学习计时长度可调整，暂不规定统一的25分钟节奏。

### 5.7 信息与工具衔接

- 每门课常用资料链接、作业说明、简短笔记。
- QQ 文字转待办：先复制粘贴，后续可增加建议提取，保存前核对。
- 截图识别作为远期可选功能，需要评估识别错误与上传目的地。
- 系统日历导出/订阅，区分一次性导入快照与后续自动更新。
- 多班共同空档，帮助约讨论、活动。
- 每周一分钟整理下周安排。

### 5.8 基础可靠性

- 本地保存失败时显示明确错误，保留编辑内容。
- 本地数据读取异常时不静默覆盖。
- 备份导出和合并恢复；恢复前展示数量，确认后执行。
- 个人事项不加入公开代码仓库和静态 data 目录。
- 后续提供添加到桌面、离线课表缓存与有身份验证的多设备同步。
- 网页内提示、系统日历、后台推送是不同能力；首版不承诺关闭网页后能推送。

## 7. 数据怎么保存

### 7.1 当前和第一版

| 数据 | 位置 | 行为 |
| --- | --- | --- |
| 网页代码、原始公开班级课表 | GitHub 仓库，部署至 Cloudflare Pages | 发布时更新，各设备都可读取 |
| 设置、个人导入课表 | 当前网站来源的 localStorage | 刷新仍在，仅当前浏览器；本地预览和线上网站分别保存 |
| 新增个人事项 | 独立版本化 localStorage 键 | 当前浏览器立即保存；支持导出备份与合并恢复 |
| 导出的个人备份 | 用户下载位置 | 用户自行保存或转移，恢复时校验 |

localStorage 按来源（协议、主机和端口）隔离。localhost不同端口、本地预览与线上域名之间数据不会自动共享。清理站点数据、隐私模式或更换浏览器会影响数据保留。本地启动器固定使用 `http://127.0.0.1:8765/`，避免每次启动端口变化导致读不到旧记录；已有相同主页的预览服务时复用该地址。

### 7.2 推荐云方案

推荐：Cloudflare Pages 保持前端；Pages Functions/Workers 接收经过身份验证的请求；D1 保存个人事项与同步元数据。

```text
手机/电脑浏览器的本地副本
        ↕ 登录后的同步请求
Cloudflare Pages Functions / Workers
        ↕ 按用户隔离的读写
Cloudflare D1
```

- 登录层要确认“谁在操作”，所有读写按同一用户标识隔离；单人版本可评估 Cloudflare Access 等方式，多用户版本需专门账号方案。
- D1 适合事项、状态、课程关联、修改时间等结构化数据。
- 后续有图片和文件附件时可评估 R2，数据库保存附件信息。
- 本机保存先完成，断网待同步；联网后按记录版本合并。
- 同步记录需要稳定 id、updatedAt、服务端版本、删除墓碑；冲突不能简单用整份文件覆盖。
- 在界面明确显示本机保存、待同步、已同步、失败状态。
- API 密钥和数据库凭据放服务端，前端不能包含 Cloudflare/GitHub 写入密钥。
- 当前项目仅有静态发布，尚未开通 D1、登录或个人数据云同步。第一版的本机保存不能描述为云端备份。

### 7.3 GitHub 的角色

GitHub 可以保存 JSON 备份或通过 Contents API 写文件，但写入会产生仓库提交，需要授权并处理文件版本冲突。因此建议用于代码、公开课表和明确需要的备份，不作为高频个人待办的默认数据库。

私人待办与 QQ 通知可能含个人信息；公开仓库不保存这些内容。若将来使用私有仓库备份，应作为用户可见的独立备份能力，明确目标仓库与内容，写入授权保存在服务端。

## 8. 验收场景

1. 上课点开课程记一句话，只填正文也能保存，课程关联正确。
2. QQ 群文字可直接粘贴，原文换行保留；输入 HTML 标签按文字显示。
3. “下周交”等不确定通知保存后仍保持待确认，不自动产生确定截止时间。
4. 明确选择日期和时间后，首页与列表展示一致。
5. 完成、撤销完成、编辑和回收站恢复后，刷新保持一致。
6. 无课日仍显示相关事项；切换班级不会把笔记错误归到另一班课程。
7. 备份恢复按记录 id 合并，重复导入不增加重复记录；旧备份不覆盖较新的修改。
8. 读取异常或写入空间不足时显示错误并保留原数据/编辑内容。
9. 手机窄屏、长课程名、长文字、键盘输入时均可操作。
10. 本机保存和云同步状态表达真实，不宣称首版已实现后台推送或云端存储。

## 9. 研究依据与设计推导

以下是此前检索的同行评审研究与元分析。它们支持方向，并未直接证明本产品有效。具体功能通过实际使用验证。

| 研究 | 研究结论概述 | 产品推导 |
| --- | --- | --- |
| Gollwitzer & Sheeran, 2006，Advances in Experimental Social Psychology | 事先明确何时何地如何行动的执行意图，有助于目标实现 | 可选填写具体下一步与安排时机 |
| Aeon et al., 2021，PLOS ONE，158项研究元分析 | 时间管理与学业表现、幸福感有关，很多证据属于相关关系 | 评价省心程度和时间掌控感，不单看完成数量 |
| Dunlosky et al., 2013，Psychological Science in the Public Interest | 练习测试、分散练习被评为高效用方法 | 课后回想问题与后续分散复习 |
| Stothart et al., 2015，Journal of Experimental Psychology: Human Perception and Performance | 在实验任务中仅收到手机通知也会干扰注意 | 提醒少而明确，主要服务截止、出发和重要变更 |
| Albulescu et al., 2022，PLOS ONE，短暂休息元分析 | 有助于恢复活力、减少疲劳，整体表现提升不显著 | 空档安排允许休息，计时长度可调整 |

## 13. 后续日常助手模块（通用需求摘要）

- 情境建议：根据课表、已记录事项和时间选择有依据的建议；支持语气偏好、每日缓存和手动换一句。
- 衣物录入：勾选类别，补充颜色与数量，点选或连线常用搭配，记录所需配件。
- 衣物可用性：区分可穿、待洗、洗涤与晾晒，支持批量更新，并预看后续运动安排。
- 出行准备：可设置常用出发地、跨区预算和早餐安排，避免重复累计可重叠时间。
- 天气与穿衣：结合预报、活动要求、实际衣物和个人反馈推荐组合。
- AI通过服务端调用；关键事实由程序计算和校验，支持缓存、身份验证、限流、费用上限和本地回退。
